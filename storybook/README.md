# Careers sites Storybook

Design system of the careers sites (Blue Shield of California, Stellarus, Ascendiun): guides, design
tokens per brand, every block and variation, and page templates, all rendered with the site's own code.

## Commands

```bash
cd storybook
npm install
npm run storybook        # dev server on http://localhost:6006
npm run build-storybook  # static site in storybook-static/ (host at the root of a domain)
npm run fixtures         # refresh content fixtures and generated stories from ../content
```

The toolbar **Brand** switches the theme (Page default, Blue Shield, Stellarus, Ascendiun); it can be set
in the address with `&globals=brand:stellarus`.

In a block story's **Controls** panel, expand **Block authoring** to edit supported variations,
content and configuration (for example Hero heading/image/link, Article List columns/background,
Share label/position, or Story Listing page size/sort). Unset fields preserve the original fixture;
use **Reset controls** to restore it. Controls apply before the site's normal block decoration.

**Advanced authoring → Authoring rows (HTML cells)** replaces the first block's rows with a JSON
array of rows, each containing cell HTML strings, without a block-name row. This supports all
authored cells, including additional cards, gallery images, table cells and share icons. For example,
an Accordion can use `[["First question", "<p>First answer</p>"], ["Second question", "Second answer"]]`.
Named controls apply after the row replacement. Missing content or malformed rows produce an
explicit error in the preview; reset the control or supply the required rows. Header/footer stories
instead expose their shared document HTML, preserving their authored section structure.

The **Preview** controls toggle the site header/footer or adjust the minimum preview height.
The frame still grows to fit its content. Changing a control only updates the preview, not fixtures,
DA or the website. Saving stories from the Controls panel is disabled so these experiments cannot
rewrite generated story files. Use **Reset controls** to discard preview edits.
**Actions** logs clicks, changes, form submissions and
disclosure toggles inside the preview, without recording input values. Select a story rather than a
guide documentation page to use these panels; press `A` if the addon panel is hidden.

## How it works

- `.storybook/main.js` serves the site folders (`blocks`, `scripts`, `styles`, `fonts`, `icons`,
  `favicons`) at their site paths, plus `public/` and the shared authoring helpers at `/sb-src/`.
  The site needs no build step and has no
  Storybook-specific code.
- Every story renders `public/sb-frame.html` in an iframe (`src/frame.js`). The frame loads a content
  fixture (`public/fixtures/<path>.plain.html`), moves its Metadata block into `<head>` like the server
  does, applies the selected brand as `theme` metadata, turns the cookie banner off, and imports
  `/scripts/scripts.js`: the page is decorated exactly as on the site. The iframe grows to its content.
- `public/sb-tokens.js` draws the Foundations token tables from `/styles/brand.css`, with the values
  resolved for the selected brand.
- Mock data at site paths: `/nav.plain.html`, `/footer.plain.html`, `/stellarus/nav.plain.html`,
  `/stellarus/footer.plain.html` (applied for the Stellarus brand from `/metadata.json`, as on the site), `/blog/query-index.json`,
  `/sitemap.json`, `/blog/external-stories.json`, `/tools/library/blocks.json` (one file per sheet:
  `blocks.options.json`, mapped by the frame's fetch shim).

## Files

| Path | Kind |
| --- | --- |
| `stories/guides/*.mdx`, `stories/foundations/*.stories.js` | Hand-written |
| `public/fixtures/foundations/*` | Hand-written fixtures (typography, buttons, section styles, empty page) |
| `stories/blocks/*`, `stories/templates/*` | Generated by `npm run fixtures`: one story per library example (named after its Library Metadata `name`), docs text from `blocks/<block>/README.md` |
| `public/fixtures/blocks|templates|pages`, `public/*.plain.html`, `public/blog`, `public/tools`, `public/media-da`, `public/drafts` | Generated by `npm run fixtures` from the local content export |

`npm run fixtures` reads `../content` (the local `.plain.html` export used by the local preview); it is not
committed, so run it on a machine that has the content export, then commit the regenerated files.

- Sheets missing from the export (`metadata.json`, `blog/external-stories.json`, `tools/library/blocks.json`)
  keep their current fixture; the script says so.
- A page saved from the Document Authoring source keeps `content.da.live` image addresses, which need a
  sign-in and do not load in Storybook; the script warns. Keep that page's previous fixture (and apply the
  content change to it), or export the page again from the site.

## Notes

- Photos load from their original addresses (internet connection needed).
- Fonts are self-hosted with the site: the base font Fieldwork for Blue Shield and Ascendiun (`styles/fonts.css`,
  files in `fonts/`), and Inter, Space Grotesk and JetBrains Mono for Stellarus (`styles/themes/stellarus/fonts.css`,
  files in `styles/themes/stellarus/fonts/`). Until they load, the metric-matched fallbacks are shown.
- The Storybook is kept out of the site: `storybook/*` is in `.hlxignore`, its packages and build output
  in `.gitignore`, and it has its own lint scope (root `.eslintignore`).
